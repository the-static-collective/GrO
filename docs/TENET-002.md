# TENET 002 — Cross locality without authority leakage

Status: executable cross-repository specimen

## Claim under test

The **same signed GrO tenet crossing** can arrive at two sovereign localities and produce different outcomes because admission remains receiver-local.

```text
Room A
  ↓
GrO tenet particular
  ↓
reLATTE opaque crossing
  ↓
same signed crossing
  ├───────────────┐
  ↓               ↓
Room B          Room C
RECEIVE         RECEIVE
ADMIT           REFUSE
  ↓               ↓
local GrO        no GrO
tenet appears    affordance appears
```

## What reLATTE owns

reLATTE verifies and carries the crossing, records RECEIVE, and records the receiver-local disposition.

It does not interpret the GrO tenet as gameplay.

The integration pins reLATTE at commit:

```text
87006f3265103a8abe387d81597c58aeb39b0beb
```

That mainline already proves opaque-organ crossing, file transport, LocalReceiver, signed receipts, and sovereign disposition.

## What GrO owns

GrO creates the portable tenet claim and decides how an **admitted** crossing becomes a local playable trace.

Source form:

```text
Water the young tree
```

Room B may lawfully localize that to:

```text
Refill the community rain bowl
```

while preserving the source tenet in lineage.

Room C may refuse the same crossing entirely.

## Laws proved

```text
SAME CROSSING != SAME CONSEQUENCE
TRANSPORT != ADMISSION
SOURCE AUTHORITY != DESTINATION AUTHORITY
ADMISSION != COPYING SOURCE RULES
LOCAL ADMISSION CREATES LOCAL PLAYABILITY
REFUSE != DELETE SOURCE HISTORY
```

## Carrier note

The current reLATTE opaque-organ aperture does not yet resolve external payload bytes during this round trip. TENET 002 therefore signs the compact GrO tenet body inside the donor claims and includes a content-addressed payload reference for the same body.

That is enough to prove the authority boundary and real crossing path, but it is **not** yet a proof of independently fetched payload-address resolution.

Do not quietly promote this witness into that stronger claim.

## 3D room witness

The game-room plugin exposed a useful visual law:

> A doorway must have a real destination. A decorative fake door fails Function.

Therefore the transport surface should **not** initially appear as a door.

### Room A — Source Garden
A small mail-slot / carrier aperture accepts a tenet particular. It visually promises transport only.

### Room B — Rain Room
The carrier aperture receives the crossing. Local ADMIT changes the room. Only then does a real traversable doorway become available toward the rain-bowl action space.

### Room C — Quiet Room
The same carrier aperture receives the same crossing. Local REFUSE leaves the wall closed. The receipt may remain inspectable, but no doorway is implied.

This makes the architecture itself say:

```text
DELIVERY != ADMISSION
ADMISSION MAY OPEN A DOOR
REFUSAL DOES NOT PRETEND A DOOR EXISTS
```
