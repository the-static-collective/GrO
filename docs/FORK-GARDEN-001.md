# FORK GARDEN 001

Status: executable cross-repository specimen

## Question

Can one verified Mineral seed lawfully become three different mined Mineral
descendants through three sovereign GrO localities, remain a noncanonical fork,
allow only two branches to recombine, and preserve the third branch intact while
the recombination is compressed into a bounded graph frontier?

## Root

GHoT mines one exact native Mineral:

```text
science.parameter-sweep/v0
mineral.parameter-sweep/v0
```

and earns:

```text
deterministic-exact-recompute/v0
```

verification.

GrO admits and independently reverifies the root before checkpointing it.

The root Mineral checkpoint is generation 1.

## Three rooms

The exact same addressed root enters three sovereign localities.

```text
Optimization Room
  -> mineral.optimization.landscape/v0

Terrain Room
  -> mineral.procedural-world.chunk/v0

Fractal Room
  -> mineral.fractal.tile/v0
```

Each locality:

1. independently ADMITs the same source crossing;
2. independently verifies the same source Mineral;
3. projects a different local affordance;
4. records a GrO action occurrence;
5. emits a bounded non-executable Mineral WANT;
6. produces a local reLATTE field projection + cultural uptake;
7. sends that WANT to GHoT;
8. gets a different real Mineral artifact;
9. independently exact-recomputes the child;
10. carries the child as an R10 cultural descendant;
11. independently ADMITs and verifies the child.

Each child is then checkpointed as generation 2 against the same verified root
checkpoint.

## Mineral checkpoint extension

TENET 009 previously checkpointed tenet-shaped descendants.

Fork Garden adds a bounded Mineral adapter.

A source Mineral may become a generation-1 checkpoint only after:

```text
artifact evidence verified
+
local ADMIT
```

A Mineral descendant may become a successor checkpoint only when:

```text
child evidence verified
+
reLATTE descendant lineage verified
+
verified predecessor checkpoint supplied
+
predecessor subject exactly matches child ancestor crossing/address
```

The checkpoint stores only bounded relation evidence. It does not turn the
Mineral into authority.

## Stronger fork law

Fork observation now requires verified successor checkpoints to share:

```text
same generation
same previous lineage root
same predecessor checkpoint anchor
same direct parent
```

This closes a subtle ambiguity where unrelated successors could otherwise be
mistaken for siblings if their checkpoint-generation metadata happened to
match.

```text
COMMON CHECKPOINT ROOT != COMMON DIRECT PARENT
```

Both are required.

## TENET 010 — garden fork

The three child checkpoints produce one observed fork:

```text
              ROOT
          /     |      \
         /      |       \
 optimization terrain  fractal
```

The fork says:

```text
conflict = false
canonicalBranchId = null
```

One room may project all three as coeligible.

Another room may declare `mineralClass` locally exclusive and therefore hold
all three as a local conflict.

That second projection still creates no global canon.

## TENET 011 — two branches recombine

A fourth sovereign room admits only the optimization and terrain descendants.

It observes the A+B pair as a lawful local fork and composes:

```text
optimization structure
+
procedural terrain
->
optimization-shaped terrain invitation
```

The recombination crossing names exactly A and B as parents.

The fractal sibling C is not a parent.

Creating the recombinant does not mutate A, B, or C.

```text
COMPOSITION != CANONIZATION
MERGE != ERASURE
UNCOMPOSED SIBLING != REJECTED HISTORY
```

The recombinant must itself RECEIVE and ADMIT freshly in a later locality
before becoming playable.

## TENET 012 — bounded graph frontier

After full verification of the A+B recombination, GrO creates a graph-frontier
checkpoint over:

```text
A checkpoint root
B checkpoint root
```

The frontier does not contain C because C was not part of this recombination.

That does not prune, reject, or erase C.

It simply means the A+B descendant can resume with bounded ancestry that is
specific to its actual parents.

```text
FRONTIER != HISTORY
BOUND FRONTIER != GLOBAL FAMILY TREE
```

## Closed specimen

CI runs:

```bash
node --experimental-strip-types \
  examples/fork-garden-001.mjs \
  .deps/reLATTE \
  .deps/GHoT
```

The proof requires:

- the root native Mineral verifies;
- all three rooms receive the same seed;
- each room emits a distinct Mineral WANT;
- GHoT mines three different native Mineral families;
- all three children independently reverify;
- all child crossings verify as reLATTE cultural descendants;
- all three generation-2 checkpoints share the same verified root;
- the 3-way fork has no canon and no global conflict;
- a declared local exclusive rule may produce local conflict without canon;
- A+B recombine while C remains untouched;
- the recombinant crossing contains only A+B parent crossings;
- A, B, and C byte representations remain unchanged;
- the recombinant requires fresh local ADMIT before playability;
- the graph frontier binds exactly A+B parent checkpoints;
- C remains outside that frontier without being erased.

```text

MERGE != ERASURE

```

FORK GARDEN 001 is therefore the first executable GrO garden in which one
verified computational object grows multiple real computed descendants and a
later locality composes some, but not all, of them without collapsing the
family tree into one canonical branch.
